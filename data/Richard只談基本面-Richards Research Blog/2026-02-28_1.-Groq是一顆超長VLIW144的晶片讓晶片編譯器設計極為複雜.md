----------"我認為Groq的合約比Mellanox還重要。這裡是完全的逆轉/投降。多年來我一直在攻擊 Groq。
......
快取（幾乎總是）由 SRAM 組成，但與 SRAM 不同。
Cache is (almost always) made of SRAM but is not the same as SRAM.

執行時，運算核心需要決定哪些記憶體應該放在哪裡。例如，某個變數應該被儲存在 L1 以取得超高速存取，還是踢到 L3 以快速存取，或是因為它不重要而直接被踢回 DRAM？
During runtime, a compute core needs to decide what memory should go where. For example, should a particular variable be stored in L1 for super fast access, or kicked to L3 for fast access, or kicked all the way to DRAM because it’s not important?

如果硬體在做這些決策，SRAM（片上記憶體）就是一個快取。
If the hardware is making these decisions, the SRAM (on-chip memory) is a cache.

如果軟體做出這些決定，SRAM（仍是片上記憶體）就是一個「暫存板」，而不是快取。
If software makes these decisions, the SRAM (still on-chip memory) is a “scratchpad”, NOT A CACHE.
......
這是一個非常重要的細微差別，但大多數公共論述都完全搞砸了。坦白說，真讓人火大。徹底改變系統的非常基本的面向，從記憶體位址映射到硬體複雜度計算，再到程式設計模型。

在評估電腦架構時，使用原則 #1（記憶體階層）時，你應該問的關鍵問題：

系統是用快取還是暫存板？
未命中快取的懲罰是什麼？
有沒有多層快取或暫存墊？
快取/暫存墊與 DRAM 或其他記憶體層的比例是多少？
......
[1] 高級運算核心會採用很酷的策略，例如分支預測、推測執行和亂序執行。這些策略都會以某種方式「破壞」原始編碼。硬體本身會即時找出組合語言程式碼中的捷徑。 高級電腦（基本上是 CPU）能大幅提升效能，但代價是佔地/功耗和平行性/可擴展性。這就是 CPU 對 AI 來說很差的主要原因。
[1] Fancy compute cores use cool strategies such as branch prediction, speculative execution, and out-of-order execution. These strategies all “break” the original complied code in some way. The hardware itself figures out shortcuts in the assembly code in real-time. Fancy computers (CPUs basically) give great performance boosts at the cost of area/power and parallelism/scalability. This is the main reason CPUs suck for AI.

[2] GPU 與 CPU 的根本區別在於曲速/波浪的概念。
......
單指令、多資料（SIMD）是GPU運作的架構原則。Nvidia 使用 32 元素的「warps」，而 AMD 則使用 64 元素的「波形」數據中心。所有 AMD 架構都是 wave64，但幾年前他們把遊戲架構換成 wave32。
......
多年來，CPU 加入了 SIMD 指令。很多 SIMD 指示......
......
GPU 主導 AI 工作負載，因為它們（這說法太簡化了......）大多是純 SIMD 機器，而 CPU 則是直接裝上 SIMD 的。
......
我們來談談資料格式與稀疏性。

過去，只有單精度（32位元）和雙精度（64位元）浮點數才是關鍵。

有了 AI，浮點數和智力都只剩 4 位元。

例如，Cerebras 愚蠢地不支援 8 位元浮點數點數點數點數。但他們仍然不支援這個基本功能。Nvidia 已經有 4 位元浮點數點數點數，AMD 也很快會支援 FP4。
......
低精度的資料格式會損失一些準確度，但吞吐量會大幅提升。......經過一些努力，準確度的懲罰可以變得微乎其微。
......
簡短回答（過於簡化）是......

VLIW = SIMD，但指令可以各有不同，但有許多限制。

一組「指令」（例如......1 個負載、5 個多重、2 個加成、1 個儲存、2 個分支）以區塊形式運作。編譯器必須排程每個套件/區塊。

硬體設計非常簡化，編譯器負擔卻是撒旦惡夢。
......
最簡單的晶片對晶片（c2c）通訊結構是全對全。

Nvidia 採用全被動銅線，這在效能和彈性上是最好的，但成本和可靠性卻是最差的。多問問大家關於傳奇的有線背板。:)

每張 GPU 都能透過單一跳點與 NVL72 域內的任何 GPU 通訊，且帶寬全。

Google 的 Ironwood TPU 使用了 3D 環面。

每塊 4x4x4（64） TPU 晶片在機架內電氣連接。跨機架連接為光學，透過基於 MEMS 的 OCS。

這比 Nvidia 的策略更可靠且具成本效益，但使編譯器的彈性大幅降低。程式設計師需要考慮網路的不均勻性，無論是延遲還是頻寬不對稱。
This is much more reliable and cost effective than Nvidia’s strategy but makes the compiler far less flexible. Programmers need to account for the non-uniformity of the network, both in terms of latency and bandwidth asymmetry.

最後，還有未來 TPU 將採用的蜻蜓拓撲。真正的 Broadcom 製 TPU。
Finally, there is the dragonfly topology future TPUs will use. The real TPUs made by Broadcom.
......
AMD 採用巢狀環形架構作為 NoC。每個 CCD（CPU 核心晶片組）都是連接到 I/O 晶片的環形。所有記憶體介面也都連接到 I/O 晶片。

特殊 SKU（-X 系列）則有額外的 SRAM 晶片與 CCD 骰子混合結合。

這個策略會讓 L3 發生巨大的快取 SRAM 消滅。由於物理區域性，L3 延遲受到輕微影響。
......
我想確保沒有人遺漏的關鍵點如下：

AMD -X SKU 擴充快取 SRAM。特別是 L3 快取。

儘管 AMD 公開宣稱不會有延遲影響，Chips and Cheese 的獨立測試卻顯示出一些輕微或奇怪的效能損失。

將 SRAM 疊加在運算之上非常困難。AMD 選擇避免此問題，僅將 SRAM 晶片堆疊在現有 SRAM 之上。注意 CPU 核心上方有兩個「結構性」（間隔器）晶片。

AMD 的設計選擇對於理解 Groq 與 D-Matrix 的路線圖具有啟發性。

Intel Saphire Rapids 採用較傳統的網狀 NoC。記得，DRAM 資料要傳送到中間的核心需要多跳。另外要注意，某些片上加速器（mini ASIC）如 QAT 和 DSA，則是獨立區塊，並有專用的網狀節點。

快取（SRAM）透過紫色區塊分散分布。

請注意，AMD 每顆 8 核心 Genoa CCD 擁有 32 MB 的共享 L3 快取，而 Intel 則選擇將 L3 快取設為每核心區塊 1.875 MB 的私有。

重點：
快取/SRAM 設計有許多取捨。

較大的共享快取意味著更多延遲，但所有運算核心都能使用相同的記憶體。

大塊的 SRAM 不一定比較好。

這很大程度上取決於核心微架構和 NoC 設計。

Hybrid Bonding
One obvious way to improve Groq-style architecture is to used hybrid-bonding to expand the SRAM scratchpad. You can get say ~2X capacity with minimal latency penalty using hybrid bonding offerings from TSMC or Intel Foundry. Groq did not have the resources to pursue this. Nvidia can handle this!

The latency penalties don’t matter anyway as the compiler needs to be deterministic and will just back out the delays ahead of time.
